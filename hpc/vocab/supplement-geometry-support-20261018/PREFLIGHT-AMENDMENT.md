# Preflight Monte Carlo amendment

Author: James Edward Ball. 18 October 2026, before any registered development or confirmation outcomes under this supplement.

The parent independently reviewed the conservative requirement that the Wilson 95% interval for null rejection lie wholly within [0.035,0.065]. With 1,000 repetitions, only rejection counts 47 to 49 meet that condition. If the true rejection probability is exactly 0.05, the probability of admission is only 0.1682061072. Four independent such gates would jointly admit with probability about 0.0008005. The low admission probability follows from the Monte Carlo rule, before observing any calibration result.

The confirmation sample size is therefore changed prospectively and uniformly to 5,000 for every beta-zero scenario, including the independent-text, fixed-design and fourfold-support diagnostics. Beta-0.4 scenarios retain 1,000. Development retains 64 per scenario and the pilot retains two per scenario. All use 499 bootstrap draws. The configuration now records `confirmation_null_replicates: 5000`. There are 47,000 confirmation repetitions: eight zero-beta scenarios and seven planted scenarios. No selective extension is allowed after outcomes.

At N=5,000, allowed null rejection counts are 201 through 290, with admission probability 0.9945164895 at true size 0.05. Four independent gates jointly admit with probability about 0.978246; this illustrative calculation does not assume the actual paired gates are independent. N=2,000 would admit counts 87 through 108 and probability 0.7288039848. The larger fixed count keeps the conservative Monte Carlo gate useful while retaining all original acceptance bands. These probabilities use the exact binomial CDF and the same Wilson formula used for reporting.

The original declared text is preserved in `PROTOCOL.md`; this dated preflight amendment supersedes its uniform confirmation count. A full-draw pilot will measure resource requirements. Resource pressure may change bounded CPU scheduling or wall time, but will not thin bootstrap draws, scenarios or confirmation counts.

A separate review identified that cell-weight effective support counts several cells separately when they share one spatial-block multiplier. The implementation now reports that quantity explicitly as cell-weight ESS and also reports independent-block ESS. For class c, aggregate the weighted cell mass within each block, M_cb, and use (sum_b M_cb)^2 / sum_b M_cb^2. This correction affects support diagnostics only and changes no estimator or acceptance gate.

Independent implementation review also clarifies the aggregate DGP boundary. Class-cell means have class-specific conditional signals and route/class-cell innovations; the physical-window innovation component alone is shared across co-occurring labels. These are exact Gaussian averages for the stated shared window-noise component. The generator does not assign one complete feature vector to each physical window and reuse that complete vector across all its labels. Thus it validates a class-cell prototype model with shared window-noise covariance. It cannot, by itself, establish coverage for the full multi-label image-level data-generating process. This clarification corrects an overly broad sufficient-statistic interpretation without changing the frozen model or code. Empirical admission remains blocked pending model applicability evidence or a separately declared physical-window simulation.
